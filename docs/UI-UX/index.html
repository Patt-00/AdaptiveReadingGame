What to build first

  1. Shared UI foundations: serif typography, menu buttons, burgundy/gold panels, answer-selection states, confirmation cards, sidebar, save-slot card.
  2. Account and menu routes: 01-10 and Logout 34. Replace the prototype’s in-memory account map with the agreed authentication service.
  3. Story navigation: 11-16 and pause/return 26. Story choices affect narrative only.
  4. Reading Checks: 17-22b. Build one reusable view; store first submissions; provide passage-based feedback and real question data.
  5. Results and difficulty: 23-25, then 40/37. Java validates difficulty and provides bounded-time fallback if the optional model is unavailable.
  6. Persistence and navigation safety: 27-31, 33, 35, 38-39. Show success only after the write finishes; never destroy a valid save on failure.
  7. Settings and accessibility: 32, keyboard focus, readable sizes, password visibility as a deliberate click/keyboard action, no timed assessments.

Contracts the team must agree on

  • Save capacity: this reference preserves the ZIP’s six-slot page and ten-page indicator. Those are UI placeholders; do not infer that storage supports sixty saves. Agree on capacity/page mapping before integration.
  • Continue: resume the latest eligible checkpoint for the logged-in player. No checkpoint means disabled Continue; final-story behavior needs an explicit decision.
  • Resume: hold scene, branch, question index, selected answer, and all submitted first attempts. Menu Return, load, and login must not accidentally reset answers or scoring.
  • Result example: 80%, Medium, and fallback Easy are sample values, not final thresholds. Use the actual Java policy.
  • Story and assessment copy: the ZIP’s introduction is a placeholder. Added story and question copy is illustrative, not a finished content bank.
  • Progress before analysis: record submitted answers and completion before optional model inference. A failure still gives usable results and a next step.

Accessibility / intentional refinements

Chapter headers use the existing dark burgundy on white instead of low-contrast gold. Selected answers have a visible marker as well as color. New error copy explains recovery, and modal Cancel restores the caller. Final accessibility checks should use the actual Georgia font and JavaFX layout.

Preview limitations

The preview follows representative paths. Questions 2-4 are skipped between feedback and the final question; story branches share a sample continuation. Forms, sliders, save persistence, model calls, and credentials are not implemented. Navigation history and the captured caller let Cancel and Return restore the reference screen.
